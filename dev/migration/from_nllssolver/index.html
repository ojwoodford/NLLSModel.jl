Migrating from NLLSsolver.jl

NLLSsolver.jl has been refactored into two modular packages:

  1. SecondOrderOptimization.jl: General-purpose, zero-allocation second-order nonlinear optimizer.
  2. NLLSModel.jl: Nonlinear least squares factor-graph modeling, automatic differentiation, robust kernels, and block-sparse assembly.

NLLSsolver.jl remains available as a 100% backward-compatible umbrella package that re-exports both SecondOrderOptimization and NLLSModel.

Key Changes

1. Model Struct Simplification & CostStruct

In previous versions of NLLSsolver.jl, NLLSProblem carried internal optimization scratch buffers (varnext and varbest), and stored costs in a Dict-backed VectorRepo. In NLLSModel.jl, Model stores only the model data, using a zero-overhead tuple-backed CostStruct parameterized on the concrete cost types (DataType, Union, or Tuple of concrete cost types):

  • costs::CostStruct{CostTypes, CostVecs}
  • variables::Vector{VarTypes}
  • varcostmap::SparseMatrixCSC{Bool, Int}
  • varcostmapvalid::Bool

All optimization scratch buffers (variables, varnext, varbest) live inside SecondOrderOptimization.OptimizationInternal and OptimizeCache (OptimizationWorkspace). problem.varnext and problem.varbest no longer exist on Model; callbacks receive the trial point from the optimizer instead.

2. Decoupled Architecture & optimvars

NLLSModel.jl and SecondOrderOptimization.jl do not depend on each other:

  • NLLSModel.jl provides optimvars returning (f, fdf!, x0, H) for any Model, and, when SecondOrderOptimization is loaded, optimize!(model, options) and optimize(model, options).
  • SecondOrderOptimization.jl provides optimize!(x0, HessianObjective(f, fdf!; H), options) and optimize(x0, obj, options) along with OptimizationOptions, OptimizationResult, OptimizationIterator, OptimizationInternal, and OptimizationWorkspace.
  • NLLSsolver.jl ties both packages together for its own problem type and provides optimize!(problem, options), optimizesingles!(problem, options), and the backward-compatible aliases (NLLSOptions, NLLSResult, NLLSIterator, NLLSInternal, OptimizeCache).

3. Separation of Concerns

If you want to optimize a smooth scalar objective f(x) with an in-place gradient/Hessian function fdf!(g, H, x) without constructing a Model factor graph, you can now use SecondOrderOptimization.optimize(x0, HessianObjective(f, fdf!), options) directly.
